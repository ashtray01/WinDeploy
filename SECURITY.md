# Security policy

## Поддерживаемые версии

Сейчас поддерживается только последняя public beta `0.1.0-beta.x` для Windows 11
x64. Windows 10/LTSC, Windows 7 и сторонние сборки не входят в заявленную
поддержку beta.

## Как сообщить об уязвимости

Не открывайте публичный Issue с деталями уязвимости, паролями, токенами,
приватными адресами или логами, содержащими пользовательские данные.

После публикации репозитория используйте GitHub **Security → Report a
vulnerability** (private vulnerability reporting). Если этот канал недоступен,
свяжитесь с владельцем репозитория через его публичный профиль GitHub и
запросите приватный канал. Конкретный email намеренно не выдумывается.

В сообщении укажите:

- версию WinDeploy и Windows build;
- затронутый сценарий и границу привилегий;
- шаги воспроизведения и ожидаемое/фактическое поведение;
- минимальный обезличенный фрагмент лога без секретов;
- возможное влияние и известные обходные пути.

Не прикладывайте реальные пароли, токены, ключи, приватные сети и персональные
данные. Если секрет уже попал в отчёт, считается скомпрометированным: его нужно
ротировать.

## Модель безопасности

WinDeploy — локальное desktop-приложение, которое по явной команде пользователя
меняет программы и настройки Windows. Приложение не является песочницей и не
защищает от администратора, который уже контролирует машину.

- Нет автоматического повышения прав и elevated worker с impersonation.
  Пользовательские изменения требуют совпадения SID процесса и владельца
  интерактивного shell; иначе операция отклоняется.
- Сессии и checkpoint находятся в пользовательском каталоге. Перед изменяющим
  resume проверяются owner и write-ACE; это не аутентификация автора файла и не
  защита от same-user/administrator tampering.
- Пакеты проверяются по SHA-256 и/или Authenticode; отсутствие обязательной
  подписи — fail closed. Каталог и версии закреплены, но это не гарантирует
  безопасность будущих версий установщиков.
- SMB-пароль передаётся Windows Credential Manager в памяти и не должен попадать
  в отчёты/логи. Отчёты не содержат parameters задач.
- Сетевые проверки и Inventory read-only. Отдельные экспериментальные страницы
  могут менять систему после подтверждения.
- EXE beta не подписан сертификатом code signing; Windows SmartScreen может
  предупредить. Проверяйте `SHA256SUMS.txt` из Release.

## Что считать особенно опасным

- обход SID/owner gate и выполнение user-scoped операции в чужом контексте;
- выполнение установщика, не соответствующего закреплённому hash/подписи;
- path traversal, подмена session ID или загрузка повреждённого/огромного
  state-файла;
- утечка пароля SMB, токена, приватного ключа или персональных данных в
  report/log;
- ложный `Success`, когда эффект не подтверждён;
- скрытое изменение системы без подтверждения.

## Disclosure

До исправления и согласования с владельцем не публикуйте exploit или
конфиденциальные данные. После исправления координация публикации выполняется
через GitHub Security Advisory.
