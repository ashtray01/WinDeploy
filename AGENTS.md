# WinDeploy: инструкции агентам

- Начните с `git status`, текущей ветки и `git log -20 --oneline`; прочитайте AGENTS.md, HANDOFF.md, TASKS.md, README.md и относящуюся к задаче архитектурную документацию/исходники. Git и работающий код важнее старых галочек. Полный аудит — docs/AUDIT.md; не повторяйте его без причины.
- Основная платформа — Modern Windows 11 x64 и Windows 10 x64, включая совместимые LTSC. `desktop/modern` уже реализован: Wails/React/TypeScript и реальные изменяющие bridge methods. Наличие страницы не доказывает работоспособность сценария.
- Windows 7/Legacy — FROZEN. Не добавлять Legacy features, Legacy-only fixes/tests и не начинать Win7 VM-матрицу без отдельного решения владельца. Не удалять существующие код, тесты и документацию; Legacy не блокирует Modern.
- Root остаётся Go 1.20; версию автоматически не повышать. Сохраняйте достигнутую совместимость, если она не мешает Modern. Modern-specific зависимости изолируйте в отдельном модуле. Конфликт совместимости документируйте с обоснованным решением. Не устанавливайте старый toolchain на каждой сессии.
- Одна итерация — 2–4 логически связанные законченные задачи, если пользователь не задал другой объём. Сначала P0, затем реальные сценарии P1. Не переходить автоматически к новым крупным этапам; не переписывать работающие компоненты и не создавать фиктивный Success.
- Бизнес-логика вне UI, небольшие интерфейсы/DI, context cancellation, Windows API в адаптерах. Проверяйте реальный результат операции, пользователя/SID и user/machine scope; preview не заменяет runtime safety gate.
- Для каждой задачи задайте критерии готовности и проверки. После изменения: diff, gofmt, релевантные test/vet/build; для frontend — strict typecheck, существующие UI tests/build и lint при наличии. Для desktop отличайте сборку от настоящего EXE/bridge smoke. Недоступные проверки указывайте явно; fake-тесты не доказывают production readiness.
- После логического изменения обновите статус и сделайте осмысленный отдельный коммит (`feat`, `fix`, `test`, `docs`, `chore`). Добавляйте только нужные файлы. Не меняйте глобальную Git identity, не перезаписывайте чужую работу, не используйте force push/reset hard. При разрешённой параллельной работе обязательны отдельные branches/worktrees.
- Не коммитить secrets, credentials, EXE, caches, runtime logs или inventory с персональными данными. Sessions требуют trusted local storage и Windows ACL; 0600 не является гарантией ACL.
- Реальные установки ПО/драйверов/принтеров, SMB с credentials, политики и настройки Windows проверять в изолированной VM. Read-only Inventory/диагностика допустимы на хосте. Не запускать неизвестные EXE, не повреждать профили и не отключать Defender/UAC/Firewall. Изменение сети требует preview, сохранения старых настроек и явного подтверждения; повышение прав — контролируемое.
- Не устанавливать зависимости и не создавать инфраструктуру без необходимости. Не выполнять несвязанные исследования/массовый рефакторинг.
- В конце итерации обновить TASKS.md и все разделы HANDOFF.md: этап, завершённое, коммиты, реальные тесты, проблемы, архитектура, Git, следующие 2–4 задачи, точные команды, ограничения безопасности. После документационного коммита проверить git status и остановиться.
- В отчёте указать ветку, хеши, реальные результаты и ближайшую задачу. Не называть проверку Windows 11 подтверждением Windows 10/LTSC или Win7.
