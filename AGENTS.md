# WinDeploy: инструкции агентам

- Начните с `git status`, `git log -5 --oneline`, затем прочитайте `AGENTS.md`, `HANDOFF.md`, `TASKS.md` и только относящиеся к задаче исходники.
- По умолчанию выполняйте одну небольшую задачу за сессию. При явном режиме MULTI-TASK выполняйте последовательно 5–10 задач с отдельными проверками/коммитами, обновляйте HANDOFF после каждых 2–3 задач. Указанный пользователем объём имеет приоритет. Не перепроектируйте работающие компоненты без необходимости.
- Общее ядро в `core/` совместимо с Go 1.20 и Windows 7 SP1 x86/x64. Не используйте более новые API Go или Windows. Modern UI будет отдельным модулем при необходимости.
- Держите бизнес-логику вне UI. Используйте небольшие интерфейсы, dependency injection и context для отмены. Windows API изолируйте в адаптерах.
- После атомарного изменения: проверьте diff, выполните относящиеся к изменению тесты, обновите состояние, добавьте только нужные файлы и сделайте осмысленный коммит (`feat`, `fix`, `test`, `docs`, `chore`). Не меняйте глобальную Git identity.
- Не коммитьте секреты, credentials, бинарники, кэши и runtime-логи. Не используйте force push/reset hard и не перезаписывайте чужую работу.
- При параллельной работе агентов обязательны отдельные ветки/worktree; не редактируйте одни файлы одновременно.
- Проверяйте поведение unit-тестами с fake-адаптерами. Реальные установщики, Windows API и драйверы проверяйте только в изолированной VM. Отмечайте непроверенную совместимость явно.
- Не запускайте неизвестные EXE, не повреждайте профили, не отключайте Defender/UAC/Firewall. Изменение сети требует предварительного просмотра, сохранения старых настроек и явного подтверждения. Административные действия требуют контролируемого повышения прав.
- Не устанавливайте зависимости и не создавайте инфраструктуру без текущей необходимости. Не выполняйте несвязанные исследования и массовый рефакторинг.
- Перед завершением обновите `TASKS.md` и все разделы `HANDOFF.md`: факты, тесты, ограничения, коммиты и одна конкретная следующая задача. Сохраните изменения коммитами, проверьте `git status` и остановитесь.
- В отчёте укажите реальные результаты проверок, хеши коммитов, ветку и следующую задачу. Не выдавайте mock-тесты за подтверждение production-готовности.
