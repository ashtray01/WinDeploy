## Архитектурные решения
Целевое требование ядра — Go 1.20. Использованы только базовые API стандартной библиотеки; проверка старым toolchain остаётся обязательной.
Task — сериализуемое описание. Будущие precheck/execute/verify — отдельный интерфейс с context; не хранить функции в Task. Нулевой статус недопустим, Pending задаётся явно. Parameters — map[string]string без секретов. Error в TaskResult должен очищаться вызывающей стороной.
UI и Windows-адаптеры отделены от бизнес-логики. Непонадобившиеся каталоги и внешние зависимости не создавались.
OrderTasks использует алгоритм Кана с выбором наименьшего исходного индекса среди готовых задач. Сложность O(V² + E); для текущих небольших планов дополнительная структура приоритетов не вводилась. Результат — новый срез поверхностных копий: вложенные maps/slices разделяются, это явно указано в API. Диагностика цикла перечисляет неразрешённые задачи, в том числе заблокированные циклом.
