# Сеть и сетевые папки

Два независимых модуля: `core/network` (диагностика только для чтения) и `core/shares` (подключение UNC, безопасные учётные данные, ярлыки). Оба используются Modern GUI и CLI `windeploy-inspect network`.

## Диагностика

Проверки: DHCP-конфигурация, системный DNS, конкретный DNS-сервер, ICMP шлюза, TCP-порт, HTTP(S), SMB-порт 445. Каждая проверка ограничена собственным таймаутом (по умолчанию 4–5 с), общий запуск — до 90 с; отмена родительского context прекращает работу и возвращает частичный отчёт.

- DNS: системный resolver (`localhost`, корпоративные имена).
- DNS-сервер: запрос идёт напрямую на настроенный сервер по UDP/53, а не через кэш.
- DHCP: адаптер подключён, IPv4 включён, при DHCP выданы шлюз и DNS; статическая настройка отмечается отдельно.
- ICMP: `ping.exe -n 1 -w 1500`; недоступность самого помощника отличается от недоступности узла.
- TCP/SMB: реальное TCP-подключение; SMB проверяет порт 445.
- HTTP: GET с ограничением редиректов и проверкой статуса < 400.

Результаты содержат статус `ok`/`failed`/`timeout`/`skipped`/`unsupported`, код ошибки, задержку и безопасное пояснение. Сеть не изменяется.

CLI:

```powershell
bin\WinDeploy-Inspect-Windows-x64.exe network --dns localhost --tcp fileserver:445 --smb fileserver --http https://example.com/ --json
```

Автоматически добавляются DHCP и ICMP шлюза для подключённых адаптеров.

## Сетевые папки

`shares.Manager.Add` проверяет UNC `\\server\share`, подключает через WNet (`WNetAddConnection2W`), сохраняет пароль в Windows Credential Manager и при необходимости создаёт `.lnk` на рабочем столе.

- Учётные данные хранятся как generic DPAPI-credential с таргетом `WinDeploy:share:<server>` — отдельно для каждого сервера. Пароль не попадает в профили, журналы, командную строку и отчёты; доменный тип credential отклонён, так как Windows не сохраняет произвольный blob вне домена.
- Подключение выполняется через `WNetAddConnection2W` с паролем в памяти; persistent-флаг включает восстановление при входе.
- Error 1219 (конфликт учётных данных) распознаётся и возвращается как типизированная ошибка с перечнем существующих подключений. Только после явного подтверждения менеджер перечисляет подключения к тому же серверу, закрывает их (`WNetCancelConnection2W`) и повторяет подключение.
- Существующие подключения читаются через `WNetOpenEnumW/WNetEnumResourceW`; выводится только безопасная информация.
- Ярлык создаётся нативно через COM `IShellLink`/`IPersistFile`; каталог рабочего стола берётся из Known Folder API (учитывает OneDrive-перенаправление). Ошибка ярлыка не отменяет подключение, а попадает в предупреждения.
- После подключения менеджер подтверждает факт подключения через перечисление WNet.

GUI: страница «Сетевые папки» — форма UNC/имя/пользователь/пароль, флаги persistent и ярлыка, кнопка «Проверить» (dry-run без изменений) и «Подключить» с отдельным подтверждением. Конфликт 1219 показывает кнопку «Закрыть конфликтующие сеансы и подключить». Список текущих подключений обновляется отдельно.

## Проверено на текущей Windows

- Core-тесты Go 1.20 amd64+386 PASS; vet PASS.
- Реальная диагностика: системный DNS, прямой DNS-сервер, TCP 445, HTTP-ответ локального сервера, DHCP-статусы адаптеров; ICMP-шлюз честно отмечен как недоступный.
- Windows Credential Manager: запись/чтение/удаление тестового credential — PASS.
- WNet enumeration — PASS (без изменения системы).
- Создание `.lnk` через нативный COM — PASS, проверен заголовок файла.
- GUI: 23 UI-теста, включая страницы диагностики и сетевых папок; реальный desktop smoke заблокирован сбоем WebView2 в среде хоста.

## Ограничения

- Подключение к реальному SMB-серверу с проверкой пароля не выполнялось: нужен изолированный сервер/VM.
- Учётные данные сохраняются только по явному действию пользователя в GUI; автоматическое применение shares-компонентов профиля появится вместе с исполнителем задач.
- Persistent-подключение может потребовать ввода пароля Windows при входе, если Windows не использует сохранённый generic credential автоматически; WinDeploy при повторном подключении читает его сам.
- ICMP может блокироваться политикой; это отображается как ошибка проверки, а не скрывается.
