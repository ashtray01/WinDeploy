# Package Manager

Каталог программ, реальная детекция, проверенная загрузка и установка. Реализация — `core/packages` (Go 1.20, без UI), каталог — `catalog/packages.yaml`, CLI — `cmd/windeploy-packages`, GUI — страница «Установка ПО» в `desktop/modern`.

## Каталог

Строгий YAML: версия схемы 1, неизвестные поля/дубликаты/якоря запрещены, размер ограничен 1 МиБ. Встроено 12 программ: 7-Zip, Google Chrome, Mozilla Firefox, Яндекс Браузер, Telegram Desktop, TG WS Proxy, MAX, VLC, MPC-HC, SumatraPDF, IrfanView, PrinterOne.

Пакет содержит ID, имя, издателя, категорию, требования Windows/архитектуры, правила обнаружения и источники. Проверка каталога не обращается к сети и не меняет систему.

Источник (`sources`) имеет приоритет, тип (`winget`, `http`, `file`), тип установщика (`exe`, `msi`, `portable`), SHA-256, тихие аргументы, коды успеха/повтора и ожидаемого издателя. Правила:

- `http` — только HTTPS, обязательный закреплённый SHA-256 (или явный режим `integrity: signature` с ожидаемым издателем);
- `file` — локальный/USB/SMB путь с `%ENV%`-переменными; хеш проверяется при установке;
- `winget` — WinGet сам проверяет SHA-256 манифеста; ID валидируется, командные метасимволы в аргументах запрещены;
- приоритет 0 — WinGet, 5 — локальные файлы `%ProgramData%\WinDeploy\Packages`, 10 — официальный HTTPS. При отсутствии WinGet выбирается локальный файл, затем HTTPS.

Офлайн-источники рассчитаны на заранее подготовленный каталог `%ProgramData%\WinDeploy\Packages` с именами файлов, указанными в каталоге.

## Детекция и план

Детекция читает только реестр Uninstall (HKLM/HKCU, обе разрядности), MSI ProductCode и файлы/portable-пути (поддерживаются маски). Ошибка чтения реестра — «неизвестно», а не «не установлено». Версии сравниваются по числовым компонентам с корректной обработкой `1.2` = `1.2.0` и суффиксов.

Действия плана: `install`, `update`, `up-to-date`, `unavailable`, `incompatible`, `unknown`. Уже установленная актуальная версия никогда не переустанавливается. Неизвестное состояние и несовместимость ОС блокируют установку вместо слепого запуска.

## Установка

`Manager.Install` выполняет выбранные пакеты последовательно:

1. повторная детекция и выбор источника;
2. проверка прав администратора до первой операции;
3. загрузка в кэш `%LOCALAPPDATA%\WinDeploy\Downloads` (или явный каталог) с потоковым SHA-256 и атомарной записью;
4. повторное использование только проверенного кэша;
5. Authenticode-проверка (WinVerifyTrust + извлечение субъекта сертификата) и сверка издателя, если он задан;
6. тихий запуск: `msiexec /i … /qn /norestart` либо EXE с аргументами каталога; portable копируется в целевой каталог;
7. классификация кода выхода: 0/заданные коды — успех, 3010/1641 — успех + перезагрузка, 1618 (MSI занят) и `retry_codes` — повтор, остальное — ошибка;
8. повторная детекция; при `RebootRequired` статус `reboot-required`, проверка переносится на после перезагрузки.

Коды ошибок стабильны и переводятся в UI: `elevation-required`, `download-failed`, `hash-mismatch`, `signature-failed`, `source-unavailable`, `install-failed`, `verify-failed`, `cancelled`.

## CLI

```powershell
bin\WinDeploy-Packages-Windows-x64.exe list
bin\WinDeploy-Packages-Windows-x64.exe plan [-id sevenzip,printerone] [-no-winget] [-json]
bin\WinDeploy-Packages-Windows-x64.exe download -id sevenzip -cache D:\cache [-no-winget]
bin\WinDeploy-Packages-Windows-x64.exe install -id sevenzip -yes
```

`install` без `--yes` отказывается работать; без прав администратора возвращает код 6. `--dry-run` проверяет план без изменений. `--no-winget` имитирует машину без WinGet и проверяет локальные/HTTPS-источники.

## GUI

Страница «Установка ПО» показывает состояние каждой программы, действие, источник, версию, SHA-256/подпись и требования. Выбор отмечается галочками; при отсутствии прав администратора системные установщики блокируются с объяснением. Установка идёт в фоне: прогресс, текущая программа, журнал событий, отмена, итоговая таблица с кодами выхода и перезагрузкой. Пароли и параметры в bridge не передаются.

## Проверено на текущей Windows

- Go 1.20.14: `go test/vet/build ./...` для windows/amd64 и windows/386 — PASS.
- Реальная детекция установленных 7-Zip 25.01, Chrome, Firefox, Telegram, VLC, SumatraPDF, IrfanView.
- Реальные HTTPS-загрузки с SHA-256 из каталога: 7-Zip 26.05 (1.6 МБ), SumatraPDF 3.6.1 (10.6 МБ), PrinterOne 1.0.1 (20.6 МБ); повторный запуск использовал проверенный кэш.
- Authenticode: подписанный системный/вендорский бинарник проходит проверку, неподписанный файл отклоняется.
- WinGet обнаружение: App Execution Alias не открывается через `os.Stat`, поэтому реализованы поиск AppX-пути и fallback через `cmd.exe`/PowerShell. В песочнице текущей сессии WinGet не получает identity пакета; это ограничение среды.

## Ограничения

- Реальная установка EXE/MSI на рабочем хосте не выполнялась (нет прав администратора и изолированной VM). Проверка установки — задача VM-матрицы.
- SHA-256 для HTTPS-источников закреплён на версию из WinGet-манифеста. При обновлении вендорского установщика по неизменяемому URL хеш перестанет совпадать — это осознанный fail-closed; источник WinGet остаётся основным.
- Portable-программы копируются в каталог, ярлыки/автозапуск для них не создаются.
- Удаление и обновление всех пакетов одним планом не реализовано; обновление выполняется для выбранного пакета.
- Параметры профилей (`package_ref`) пока не связаны с каталогом в Task Engine; это часть Stage 9.
