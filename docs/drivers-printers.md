# Драйверы и принтеры

Реализованы `core/drivers` и `core/printers` (Go 1.20, Windows-адаптеры), страницы Modern «Драйверы» и «Принтеры», а также read-only команды CLI `windeploy-inspect devices|printers`.

## Драйверы

### Устройства

`drivers.WindowsDevices` перечисляет присутствующие PnP-устройства через SetupAPI: имя/friendly name, класс, производитель, instance ID, Hardware ID (REG_MULTI_SZ), установленный драйвер (версия и поставщик из ключа класса) и код проблемы из `CM_Get_DevNode_Status`. Неизвестным считается устройство с кодом 28 или проблемой без драйвера и класса. Чтение не требует прав администратора.

### Каталог INF

`drivers.ScanDirectory` обходит локальный или сетевой каталог (глубина ≤3, ≤2000 INF, ≤1 МиБ на файл) и парсит `[Version]`, `[Manufacturer]`, модельные секции и `%Strings%`. Поддерживаются UTF-8 и UTF-16LE (BOM/без BOM). `FindForHardwareID` возвращает INF, где Hardware ID устройства указан точно.

### Установка

`drivers.Manager.Install`:

1. проверяет INF (расширение, существование, размер);
2. `SetupVerifyInfFileW` проверяет подпись каталога/INF и совместимость с текущей платформой/архитектурой — неподписанный пакет отклоняется (`ErrUnsignedINF`);
3. dry-run завершается до изменений;
4. без elevated-токена установка не начинается (`ErrElevationRequired`);
5. `pnputil /add-driver <inf> /install` (Windows 10/11) или `pnputil -i -a` (Windows 7); для 32-битного процесса используется `%SystemRoot%\Sysnative\pnputil.exe`;
6. коды 0/3010/1641 — успех, 3010/1641 добавляют RebootRequired; иная ошибка — fail-closed;
7. после установки устройства перечисляются заново; успех подтверждается только найденным устройством с тем же Hardware ID и статусом `ok`.

`WindowsInstaller.ScanDevices` запускает `pnputil /scan-devices` — совместимый с политикой Windows Update поиск драйверов; на Windows 7 метод возвращает unsupported. Он не устанавливает драйверы в обход подписи и требует прав администратора.

## Принтеры

- `WindowsPrinters` перечисляет локальные и подключённые очереди через `EnumPrintersW` level 2: имя, драйвер, порт, сервер, общий ресурс, атрибуты/статус и принтер по умолчанию (`GetDefaultPrinterW`).
- `WindowsInstaller.AddPrinter` устанавливает очередь из INF и создаёт стандартный TCP/IP-порт: `rundll32 printui.dll,PrintUIEntry /if /b <имя> /f <inf> /r IP_<адрес> /m <модель> /q` (+ `/z <share>` для общего доступа). Требуются права администратора; после установки очередь подтверждается перечислением.
- `WindowsDefaults.SetDefault` использует `SetDefaultPrinterW` для текущего пользователя.
- `WindowsTestPrinter` печатает реальную тестовую страницу через GDI (`CreateDCW` → `StartDocW`/`TextOutW`/`EndDoc`). Тестовая печать выполняется только по явному подтверждению.
- Kyocera 2460: `Kyocera2460Models` содержит `TASKalfa 2460ci` и `TASKalfa 2460ci+`; для семейства 2460 установка без точной модели из списка отклоняется (`ErrModelRequired`). Список конфигурируемый; модель никогда не выбирается автоматически.

## GUI

- «Драйверы»: фильтр проблемных/всех устройств, поиск, выбор Hardware ID, сканирование каталога INF, проверка подписи без установки, подтверждаемая установка, подтверждаемый поиск драйверов через PnP/Windows Update policy.
- «Принтеры»: список очередей и принтер по умолчанию, назначение по умолчанию, тестовая страница с подтверждением, добавление TCP/IP-принтера из INF с явной моделью Kyocera 2460.

## Проверено на текущей Windows

- Go 1.20.14 amd64+386: test/vet/build PASS.
- Реальное перечисление: 212 устройств, 210 с версией драйвера, 205 с Hardware ID; проблемных устройств на хосте нет.
- `SetupVerifyInfFileW` отклоняет неподписанный INF (native test).
- `pnputil` найден и в amd64, и в 386-процессе (через Sysnative); команда `/scan-devices` проверена fake-runner-тестом, реального изменения системы не выполнялось.
- Реальное перечисление принтеров: 4 очереди, принтер по умолчанию определён и помечен.
- UI: 29 vitest-тестов, включая страницы драйверов и принтеров; strict TypeScript/Vite PASS.

## Ограничения

- Реальная установка драйвера не выполнялась: нет подходящего тестового устройства и изолированной VM. Проверка «устройство подтверждено» покрыта fake-тестами.
- Тестовая страница реально не печаталась: на хосте нет безопасного тестового принтера. GDI-путь компилируется, но требует VM/принтера для runtime-подтверждения.
- Добавление принтера, общий доступ и синтаксис `/z` printui не проверены на реальном сервере печати.
- Windows Update-механизм ограничен PnP-сканом по политике Windows; прямой COM-поиск драйверов Windows Update не реализован.
- Кросс-архитектурная установка INF (AltPlatformInfo) не используется: проверяется текущая платформа.
