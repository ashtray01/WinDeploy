# Архитектурный каркас

Корневой Go-модуль `windeploy` содержит общее ядро с директивой `go 1.20` и без внешних зависимостей. Путь модуля локальный, до появления remote не привязан к GitHub.

Реализованы только `core` (граница общего слоя) и `core/engine` (описания задач и результатов). Пустые каталоги будущих компонентов не создаются: Git их не хранит, а фиктивные реализации скрывают отсутствие функциональности.

Будущие границы:

| Путь | Ответственность |
| --- | --- |
| `core/engine` | План DAG, выполнение, отмена, управление статусами |
| `core/profiles`, `core/inventory` | Профили и факты о системе |
| `core/packages`, `core/drivers` | Установка пакетов и драйверов через адаптеры |
| `core/network`, `core/shares`, `core/printers` | Диагностика и системные операции |
| `core/browsers`, `core/security` | Настройки браузеров, credentials и повышение прав |
| `core/state`, `core/reporting` | Возобновление, журнал, отчёты |
| `desktop`, `frontend` | Modern UI; отдельный Go-модуль при несовместимых требованиях toolchain |
| `legacy` | Нативный UI, Go 1.20, Windows 7 SP1 x86/x64 |

Модель Task декларативная: параметры, требования ОС, зависимости, timeout и статус. TaskResult хранит итог, время, диагностическую строку и необходимость перезагрузки. Эти структуры допускают JSON-сериализацию, но не реализуют persistent state. Статусы в JSON совпадают с именами из ТЗ; нулевой статус недопустим. Timeout сериализуется числом наносекунд, ноль означает настройку исполнителя по умолчанию.

`Task.Validate` проверяет только локальную структуру; существование зависимостей, циклы, требования ОС и переходы статусов ещё не проверяются. Строки parameters/error не должны содержать секретов; автоматическое маскирование пока отсутствует.

Предварительная проверка, выполнение и проверка результата будут методами интерфейса адаптера с `context.Context`, отдельно от сериализуемого описания. Engine не должен обращаться к UI или напрямую запускать системные команды. Реестр адаптеров и планировщик пока отсутствуют.

Указание Go 1.20 в go.mod не доказывает совместимость: нужна проверка этим toolchain и запуск в VM. Windows-specific API следует изолировать через build tags и адаптеры; современные зависимости UI не должны попадать в общее ядро.
