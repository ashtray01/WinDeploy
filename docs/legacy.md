# Legacy Windows 7 GUI

`legacy/` — отдельное Go 1.20-приложение с нативным Win32-интерфейсом (Walk). Оно не использует WebView2, .NET, современные API Windows и общее Modern-ядро; бизнес-логика берётся из `core/` через `replace windeploy => ../`.

## Что реализовано

- Сводка компьютера: имя, версия Windows (Win7/8/8.1/10/11), архитектура, CPU, RAM, права администратора, статус лицензирования (read-only).
- Программы: каталог 12 программ, фильтрация по совместимости, определение установленных версий, установка выбранных через общий Package Manager (HTTPS, SHA-256, Authenticode, silent install, проверка, повторы), отмена, журнал.
- Сеть: read-only диагностика DHCP/шлюзов/DNS, подключение UNC-папки с паролем только в памяти и ярлыком.
- Диагностика Windows Update и лицензирования только для чтения.
- Подтверждения перед изменяющими действиями; без прав администратора установка блокируется.

## Сборка

```powershell
scripts/build-legacy.ps1 -GuiSmoke
```

Go 1.20.14, `GOOS=windows`, amd64 и 386. Манифест Common Controls 6 и `supportedOS` встроен через `rsrc_windows_*.syso`. Выход: `bin/WinDeploy-Legacy-Windows-x64.exe`, `...-x86.exe`.

`--selftest` проверяет каталог/детекцию/совместимость без окна; `--smoke` создаёт реальное окно и закрывает его через 3 секунды.

## Проверено на текущей Windows 11

- `go test ./...` и `go vet` для amd64/386 — PASS.
- `--selftest` x64/x86 — PASS (каталог 12, 7-Zip, совместимость).
- `--smoke` x64/x86 — реальное окно создано, сообщение закрытия обработано, выход 0.
- Без манифеста Walk падал с `TTM_ADDTOOL`; манифест Common Controls 6 устранил проблему.

## Не проверено

- Windows 7 SP1 VM — целевая платформа не запускалась. Текущая Windows 11 не доказывает совместимость.
- Реальные установки ПО, SMB-подключение и права администратора в Legacy.
- Walk 2021 на Win7 без обновлений; теоретически нужен только Common Controls 6, входящий в Win7, но это требует проверки.
- DPI/темы и поведение на x86 Win7.
